# Summary: this → call → apply → bind → Arrow Functions


| Concept                | Syntax                    | What happens to `this`?          | Executes immediately? | Easy way to remember                    |
| ---------------------- | ------------------------- | -------------------------------- | --------------------- | --------------------------------------- |
| **Normal function**    | `obj.fn()`                | `this = obj`                     | ✅ Yes                 | **Who called me?**                      |
| **Extracted function** | `const fn = obj.fn; fn()` | `this` is no longer `obj`        | ✅ Yes                 | Object connection is lost               |
| **`new`**              | `new Fn()`                | `this = new object`              | ✅ Yes                 | **New object becomes `this`**           |
| **`call()`**           | `fn.call(obj, 1, 2)`      | `this = obj`                     | ✅ Yes                 | **Set `this` + run now**                |
| **`apply()`**          | `fn.apply(obj, [1, 2])`   | `this = obj`                     | ✅ Yes                 | **Set `this` + run now, args as array** |
| **`bind()`**           | `fn.bind(obj)`            | `this = obj`                     | ❌ No                  | **Set `this` + get a new function**     |
| **Arrow function**     | `() => {}`                | Uses surrounding `this`          | Depends               | **Arrow doesn't have its own `this`**   |
| **Arrow + `call()`**   | `arrow.call(obj)`         | `this` does **not** become `obj` | ✅ Yes                 | `call` can't change arrow's `this`      |
| **Arrow + `bind()`**   | `arrow.bind(obj)`         | `this` does **not** become `obj` | ❌ No                  | `bind` can't change arrow's `this`      |

### `call` vs `apply` vs `bind`

| Method    | `this`         | Arguments               | Runs now? |
| --------- | -------------- | ----------------------- | --------- |
| `call()`  | Explicitly set | `fn.call(obj, 1, 2)`    | ✅         |
| `apply()` | Explicitly set | `fn.apply(obj, [1, 2])` | ✅         |
| `bind()`  | Explicitly set | `fn.bind(obj, 1, 2)`    | ❌         |

### The most important table

| Situation       | `this`                                   |
| --------------- | ---------------------------------------- |
| `obj.fn()`      | `obj`                                    |
| `fn()`          | Depends on normal-function default rules |
| `fn.call(obj)`  | `obj`                                    |
| `fn.apply(obj)` | `obj`                                    |
| `fn.bind(obj)`  | `obj` when the returned function runs    |
| `new Fn()`      | Newly created object                     |
| Arrow function  | Surrounding/lexical `this`               |

### 🧠 One-line memory trick

| Function type       | Ask yourself               |
| ------------------- | -------------------------- |
| **Normal function** | **"Who called me?"**       |
| **Arrow function**  | **"Where was I created?"** |

And the biggest distinction:

```text
call()   → run now
apply()  → run now
bind()   → run later
```

That's the core of the whole topic.


# Deep Dive: this → call → apply → bind → Arrow Functions

> **`this` usually means: “Who called this function?”**

Once that clicks, `call`, `apply`, `bind`, and arrow functions become much easier.

## 1. Start with a normal function

```js
function sayName() {
  console.log(this.name);
}
```

Don't worry about `this` yet.

We need to see **how the function is called**.

### Case A

```js
const user = {
  name: "John",
  sayName: sayName
};

user.sayName();
```

Look carefully:

```js
user.sayName();
```

Who called `sayName`?

**`user`**

So:

```text
this = user
```

Therefore:

```text
this.name
↓
user.name
↓
"John"
```

Output:

```text
John
```

# 2. Now remove the object

Same function:

```js
function sayName() {
  console.log(this.name);
}
```

Now:

```js
const fn = sayName;

fn();
```

Who called the function?

Not `user`.

There is no:

```js
user.fn()
```

It's simply:

```js
fn()
```

So the function no longer has the `user` connection.

This is why this code is dangerous:

```js
const user = {
  name: "John",

  greet() {
    console.log(this.name);
  }
};

const fn = user.greet;

fn();
```

You might think:

```text
this = user
```

But **no**.

The important thing is:

```text
user.greet()
```

and

```text
fn()
```

are two different ways of calling the function.

# 3. The most important rule

For a **normal function**, don't ask:

> "Where was this function created?"

Ask:

> **"How was this function called?"**

For example:

```js
const person = {
  name: "John",

  greet() {
    console.log(this.name);
  }
};
```

### Called like this:

```js
person.greet();
```

Then:

```text
this → person
```

### Called like this:

```js
const x = person.greet;
x();
```

Then:

```text
this → NOT person
```

That's the foundation.

# 4. Now `call()` becomes easy

Suppose we have:

```js
function greet() {
  console.log(this.name);
}
```

Normally, we might do:

```js
const user = {
  name: "John"
};

user.greet();
```

But `greet` isn't actually a property of `user`.

So we can tell JavaScript:

> "Call this function, but pretend `user` is the `this`."

That's exactly what `call()` does.

```js
greet.call(user);
```

Think:

```text
greet.call(user)
       ↓
"Run greet with this = user"
```

Therefore:

```js
console.log(this.name);
```

becomes effectively:

```js
console.log(user.name);
```

Output:

```text
John
```

# 5. `call()` with arguments

Suppose:

```js
function introduce(age, city) {
  console.log(this.name, age, city);
}
```

And:

```js
const user = {
  name: "John"
};
```

We can do:

```js
introduce.call(user, 25, "Delhi");
```

Think of it as:

```text
this = user
age = 25
city = "Delhi"
```

So output:

```text
John 25 Delhi
```

# 6. Then what is `apply()`?

Almost exactly the same thing.

`call`:

```js
introduce.call(user, 25, "Delhi");
```

`apply`:

```js
introduce.apply(user, [25, "Delhi"]);
```

The only thing you need to remember:

```text
call  → arguments separately
apply → arguments inside an array
```

That's it.

Don't overthink `apply`.

# 7. Now `bind()` — this one is different

Suppose:

```js
function greet() {
  console.log(this.name);
}

const user = {
  name: "John"
};
```

With `call`:

```js
greet.call(user);
```

The function runs **right now**.

```text
call
 ↓
run immediately
```

But with `bind`:

```js
const newGreet = greet.bind(user);
```

Nothing runs yet.

Instead, JavaScript creates another function.

```text
greet
 ↓
bind(user)
 ↓
new function
```

Then later:

```js
newGreet();
```

Now it runs with:

```text
this = user
```

So remember:

```text
call()  → run now
apply() → run now
bind()  → give me a new function to run later
```

This is probably the most important difference between the three.

# 8. Why is `bind()` useful?

Look at this:

```js
const user = {
  name: "John",

  greet() {
    console.log(this.name);
  }
};

setTimeout(user.greet, 1000);
```

We passed the function:

```js
user.greet
```

to `setTimeout`.

The function is no longer being called as:

```js
user.greet()
```

So it can lose its `this`.

We can say:

```js
setTimeout(user.greet.bind(user), 1000);
```

Now we have created a new function where:

```text
this = user
```

even when the function is called later.

# 9. Now forget everything and learn arrow functions

This is where things change.

Normal function:

```js
function greet() {
  console.log(this.name);
}
```

Normal functions get `this` based on **how they're called**.

Arrow functions are different:

```js
const greet = () => {
  console.log(this.name);
};
```

Arrow functions **don't create their own `this`**.

Instead they say:

> "I'll use the `this` from where I was created."

That's called **lexical `this`**.

You can think:

```text
normal function:
"Who called me?"

arrow function:
"I'll use the surrounding this."
```

# 10. The easiest example of why arrows are useful

Look at this:

```js
const user = {
  name: "John",

  greet() {
    const inner = () => {
      console.log(this.name);
    };

    inner();
  }
};

user.greet();
```

First:

```js
user.greet();
```

Therefore:

```text
this = user
```

Inside `greet`, we create:

```js
const inner = () => {
  console.log(this.name);
};
```

The arrow says:

> "I don't have my own `this`. I'll use the surrounding `this`."

The surrounding `this` is:

```text
user
```

Therefore:

```text
inner()
 ↓
arrow uses surrounding this
 ↓
this = user
 ↓
this.name
 ↓
John
```

# 11. Compare that with a normal nested function

This is where people get confused.

```js
const user = {
  name: "John",

  greet() {
    function inner() {
      console.log(this.name);
    }

    inner();
  }
};
```

We call:

```js
user.greet();
```

Inside `greet`:

```text
this = user
```

But then we call:

```js
inner();
```

`inner` is a **normal function**.

Who called `inner`?

Nobody called it like:

```js
user.inner()
```

It's simply:

```js
inner()
```

So `inner` doesn't automatically inherit `greet`'s `this`.

That's why people often use:

```js
const inner = () => {
  console.log(this.name);
};
```

instead.

# 12. Now let's understand classes

Suppose:

```js
class User {
  constructor(name) {
    this.name = name;
  }

  greet() {
    console.log(this.name);
  }
}
```

Create an object:

```js
const john = new User("John");
```

Now:

```js
john.greet();
```

Who called `greet`?

```text
john
```

Therefore:

```text
this = john
```

So:

```js
this.name
```

means:

```js
john.name
```

which is:

```text
John
```

# 13. But look what happens here

```js
const greet = john.greet;

greet();
```

We separated the method from the object.

Originally:

```js
john.greet()
```

had:

```text
this = john
```

But now:

```js
greet()
```

doesn't have `john` in front of it.

So the connection is lost.

This is why you see:

```js
john.greet.bind(john)
```

or:

```js
john.greet = john.greet.bind(john)
```

# 14. One picture to remember

For **normal functions**, think:

```text
                 HOW WAS IT CALLED?
                        │
          ┌─────────────┼─────────────┐
          ↓             ↓             ↓
       obj.fn()       fn.call(x)    fn()
          │             │             │
          ↓             ↓             ↓
       this=obj       this=x       default this
```

And:

```text
new Fn()
   ↓
this = newly created object
```

# 15. Arrow functions have a completely different rule

```text
              Arrow function
                    │
                    ↓
          Does it have its own this?
                    │
                   NO
                    │
                    ↓
       Use surrounding lexical this
```

That's why this doesn't work:

```js
const arrow = () => {
  console.log(this);
};

arrow.call(user);
```

`call()` can't change the arrow's `this`.

Because the arrow already got its `this` from its surrounding environment.

# 16. The whole topic in one example

Look at this:

```js
const user = {
  name: "John",

  normal() {
    console.log(this.name);
  },

  nested() {
    const arrow = () => {
      console.log(this.name);
    };

    arrow();
  }
};
```

### First:

```js
user.normal();
```

Normal function.

Who called it?

```text
user
```

Therefore:

```text
this = user
```

Output:

```text
John
```

### Second:

```js
user.nested();
```

Again:

```text
this = user
```

Then:

```js
arrow();
```

Arrow function.

Arrow says:

```text
"I'll use the surrounding this."
```

Surrounding `this` is:

```text
user
```

Therefore:

```text
John
```

### Third:

```js
const fn = user.normal;
fn();
```

Normal function.

Who called it?

```text
fn()
```

Not:

```text
user.fn()
```

Therefore:

```text
this ≠ user
```

### Fourth:

```js
const fn = user.normal.bind(user);
fn();
```

`bind` says:

```text
"Always use user as this."
```

Therefore:

```text
this = user
```

Output:

```text
John
```

# 17. Don't memorize the huge table

For now, memorize only these **5 things**:

### ① Normal function + object call

```js
obj.fn();
```

➡️ `this = obj`

### ② `call`

```js
fn.call(obj);
```

➡️ `this = obj`, **run immediately**

### ③ `apply`

```js
fn.apply(obj, [1, 2]);
```

➡️ `this = obj`, **run immediately**

### ④ `bind`

```js
const newFn = fn.bind(obj);
```

➡️ Creates a new function where `this = obj`

### ⑤ Arrow function

```js
const fn = () => {};
```

➡️ Doesn't have its own `this`; it uses the surrounding `this`.

## The one sentence I want you to remember

> **Normal function: look at how it was called. Arrow function: look at where it was created.**

If that sentence becomes intuitive, the rest of `this`, `call`, `apply`, `bind`, callbacks, and class methods becomes much easier.
